# Арифметика эллиптических кривых (Elliptic Curves Arithmetic)

Консольная программа на Python для выполнения арифметических операций над точками
эллиптических кривых над конечными полями:

- **Zp** — кривая `y² = x³ + a·x + b` над простым полем `Z_p`;
- **Nss** — несуперсингулярная кривая `y² + x·y = x³ + a·x² + b` над `GF(2^m)`;
- **Ss** — суперсингулярная кривая `y² + a·x·y = x³ + b·x² + c` над `GF(2^m)`.

Поддерживаются операции:
- **A** — сложение двух точек;
- **M** — умножение точки на скаляр `k`.

Программа может обрабатывать **один файл** задания или **целую папку** с заданиями,
складывать ответы в отдельную папку и выводить координаты точек в **десятичном**
или **шестнадцатеричном** виде.

> **Важно:** формат вывода (`hex` / `dec`) применяется **только к файлам ответов**.
> В файлах заданий каждая строка может быть в своей системе счисления — см.
> раздел [Системы счисления](#системы-счисления).

## Формат входного файла

Входной файл — обычный **`.txt`**, содержащий как минимум **3 строки** и далее
**произвольное число строк с задачами**.

### Строки 1–3: описание кривой

| № | Что задаётся | Формат |
|---|---|---|
| 1 | Тип кривой | `Zp`, `Nss` или `Ss` |
| 2 | Поле | для `Zp` — простое `p`; для `Nss`/`Ss` — неприводимый многочлен в виде `(d_k … d_1 d_0)` |
| 3 | Коэффициенты кривой | для `Zp` — `a b`; для `Nss` — `a b`; для `Ss` — `a b c` |

**Многочлен** задаётся списком степеней одночленов с ненулевыми коэффициентами,
например `(4 1 0)` означает `x⁴ + x + 1`.

**Число коэффициентов**:
- `Zp` → `a b` (уравнение `y² = x³ + a·x + b`)
- `Nss` → `a b` (уравнение `y² + x·y = x³ + a·x² + b`)
- `Ss` → `a b c` (уравнение `y² + a·x·y = x³ + b·x² + c`)

### Строки 4+: задачи

Каждая строка — одна задача одного из двух видов:

```
A (x1 y1) (x2 y2)      # сложение точек P1 + P2
M (x y) k              # скалярное умножение k · P
```

- Точка записывается как `(x y)` (можно с запятой: `(x, y)`).
- `k` — целое (может быть отрицательным).
- Пустые строки игнорируются.

## Формат выходного файла

Для каждой задачи — одна строка с результатом:

- **точка**: `(0x<x>, 0x<y>)` — если формат вывода `hex` (по умолчанию), или
  `(<x>, <y>)` — если формат `dec`;
- **бесконечно удалённая точка**: `O`;
- если на вход подана точка, **не лежащая** на кривой, перед результатом
  выводится предупреждение `# Warning: …` (координаты в том же формате).

**Куда пишется ответ:**

- при обработке **одного файла** `task.txt` без `-o` — рядом с входным,
  как `taskout.txt`;
- при обработке **одного файла** с `-o OUT` — в `OUT/task.txt`;
- при обработке **папки** `-i IN` без `-o` — в ту же папку, как `<имя>out.txt`;
- при обработке **папки** `-i IN -o OUT` — в `OUT/<имя>.txt`.

Файлы, оканчивающиеся на `out.txt`, при обработке папки пропускаются,
чтобы повторный запуск не переобрабатывал собственные ответы.

## Системы счисления

**Во входных файлах** каждая строка может использовать **свою** систему
счисления; ограничение — «в одной строке одна система»:

- **10-ричная**: `17`, `31`, `255`
- **16-ричная**: `0x11`, `0x1F`, `FF` — распознаётся по префиксу `0x`
  или по наличию букв `a–f`

Поле может быть задано в одной системе, коэффициенты — в другой, задача — в третьей.
Пример корректного файла (поле — decimal, коэффициенты — hex, задача — hex):

```txt
Zp
17
0x2 0x2
A (0x5 0x1) (0x6 0x3)
```

**В файлах ответов** система счисления задаётся **параметром запуска** `-f`:

- `-f hex` (по умолчанию) — координаты в 16-ричном виде (`0xa`, `0x6`);
- `-f dec` — координаты в 10-ричном виде (`10`, `6`).

Флаг `-f` **не влияет** на то, как читаются входные файлы: они по-прежнему
принимают `0x..`/`a-f`/десятичные в любой строке.

## Запуск

Из **корня проекта**.

> Команды ниже записаны для bash (macOS/Linux). На Windows вместо `python`
> удобнее `py`, а в путях допустимы и `\`, и `/`:
> `py -m app.main IN\zp_basic.txt -o OUT -f dec`.
> Пошаговая инструкция — [Запуск на Windows 10](#запуск-на-windows-10).

### Один файл

```bash
python -m app.main IN/zp_basic.txt
# ответ: IN/zp_basicout.txt (hex по умолчанию)

python -m app.main IN/zp_basic.txt -o OUT -f dec
# ответ: OUT/zp_basic.txt, координаты в десятичном виде
```

### Папка с заданиями

```bash
python -m app.main --in-dir IN --out-dir OUT
python -m app.main -i IN -o OUT -f dec
```

Обрабатываются все `*.txt` в `--in-dir` (файлы `*out.txt` пропускаются);
ответы кладутся в `--out-dir` под теми же именами.

### Альтернативный запуск

Если вы **не** хотите использовать `-m`, можно запускать напрямую — в `main.py`
добавлена настройка `sys.path`, поэтому из корня проекта работает и так:

```bash
python app/main.py IN/zp_basic.txt -o OUT -f dec
```

## Флаги командной строки

| Флаг | Значение |
|---|---|
| `<task_file>` | путь к одному `.txt` (позиционный; взаимоисключим с `-i`) |
| `-i`, `--in-dir` | папка с заданиями (все `*.txt` обрабатываются) |
| `-o`, `--out-dir` | папка для ответов (по умолчанию — рядом с заданиями) |
| `-f`, `--format` | `hex` (по умолчанию) или `dec` — формат координат **в ответах** |
| `-h`, `--help` | справка |

Примеры:

```bash
python -m app.main IN/task.txt                  # один файл, hex
python -m app.main IN/task.txt -f dec           # один файл, dec, рядом
python -m app.main IN/task.txt -o OUT -f dec    # один файл, dec, в OUT/
python -m app.main -i IN -o OUT                 # вся папка, hex
python -m app.main -i IN -o OUT -f dec          # вся папка, dec
```

## Примеры

### Пример 1. Кривая над Zp (десятичные числа во входе)

**`IN/task.txt`**

```txt
Zp
17
2 2
A (5 1) (6 3)
M (5 1) 3
M (5 1) 0
A (5 1) (5 16)
```

**`taskout.txt` при `-f hex` (по умолчанию)**

```txt
(0xa, 0x6)
(0xa, 0x6)
O
O
```

**`taskout.txt` при `-f dec`**

```txt
(10, 6)
(10, 6)
O
O
```

Пояснения:
- `(5,1) + (6,3) = (10,6)`;
- `3·(5,1) = (10,6)`;
- `0·(5,1) = O`;
- `(5,1) + (5,16) = O` (противоположные точки).

### Пример 2. Кривая над Zp (16-ричные числа во входе)

**`IN/zp_hex.txt`**

```txt
Zp
0x11
0x2 0x2
A (0x5 0x1) (0x6 0x3)
M (0x5 0x1) 0x3
```

**`zp_hexout.txt` при `-f hex`**

```txt
(0xa, 0x6)
(0xa, 0x6)
```

**`zp_hexout.txt` при `-f dec`**

```txt
(10, 6)
(10, 6)
```

### Пример 3. Смешанные системы счисления во входе

**`IN/mixed.txt`**

```txt
Zp
0x11
2 2
A (5 1) (6 3)
```

Все три задачи дают один результат, но входные числа записаны по-разному.
При `-f dec` ответ будет:

```txt
(10, 6)
(10, 6)
(10, 6)
```

### Пример 4. Кривая Nss над GF(2⁴)

**`IN/nss_basic.txt`**


## Тесты

В проекте есть три группы тестов:

| Файл | Что проверяет |
|---|---|
| `tests/test_curves_unit.py` | базовые свойства кривых (нейтральный элемент, отрицание, коммутативность, скалярное умножение) |
| `tests/test_group_laws.py` | полный набор групповых аксиом: ассоциативность на полном переборе, дистрибутивность, гомоморфизм, порядок группы и порядок точки, эквивалентность Nss/Ss при `a1=1` |
| `tests/test_files.py` | прогон всех файлов из `IN/` и сверка с эталонами в `OUT/` |

Запуск:

```bash
pytest -q
# или
python -m unittest discover -s tests -v
```

На Windows:

```bat
py -m unittest discover -s tests -v
:: или, если установлен pytest:
py -m pytest -q
```

Ожидается **69** тестов и `OK` (без `FAILED`).

> **Про эталоны в `OUT/`.** `tests/test_files.py` прогоняет каждый `IN/*.txt`
> и сравнивает результат с `OUT/<имя>.txt`. Эталоны записаны в
> **десятичном** виде, поэтому тест сам выставляет формат вывода
> (`set_output_base(10)`) и не зависит от значения `-f` по умолчанию;
> hex-формат проверяется отдельным тестом `test_hex_format`.
> Если вы пересоздаёте эталоны, делайте это с тем же форматом:
>
> ```bash
> python -m app.main -i IN -o OUT -f dec
> ```
>
> Папка `OUT/` входит в репозиторий: без неё `test_files` падает с
> «Нет эталона …». Тесты не зависят от порядка запуска и от текущей
> директории (корень проекта вычисляется от `__file__`).

## Запуск на Windows 10

Полный путь «с нуля» для Windows 10 x64 (cmd или PowerShell). Проекту нужен
только Python 3.10+, внешних библиотек нет.

### 1. Установить Python

1. Скачайте 64-битный установщик **Python 3.10–3.13** с
   <https://www.python.org/downloads/windows/>.
2. В установщике отметьте **«Add python.exe to PATH»** (и, желательно,
   «Install launcher for all users», чтобы работала команда `py`).
3. В **новом** окне консоли проверьте:

   ```bat
   py --version
   ```

   Должно быть `Python 3.10.x` или новее.

Если команда `python` открывает Microsoft Store, используйте `py` либо
отключите псевдонимы: «Параметры → Приложения → Дополнительные параметры →
Псевдонимы выполнения приложений».

### 2. Получить проект и создать окружение

```bat
git clone git@github.com:EvanKlokOff/elleptic_curve_course_task.git
cd elleptic_curve_course_task

py -m venv .venv
.venv\Scripts\activate
py -m pip install --upgrade pip
```

Если SSH-ключ на машине не настроен, клонируйте по HTTPS
(`https://github.com/EvanKlokOff/elleptic_curve_course_task.git`) или просто
скопируйте папку проекта — `.venv`, `.idea` и `__pycache__` копировать не нужно.

> **Не копируйте папку `.venv` с другой машины** (macOS/Linux): она привязана
> к пути интерпретатора. На Windows окружение создаётся заново — в нём
> появляется `.venv\Scripts\python.exe` вместо `.venv\bin\python`.

Если PowerShell блокирует `Activate.ps1` с сообщением
`... cannot be loaded because running scripts is disabled`, есть три варианта:

- один раз разрешить свои скрипты:
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`;
- активировать из cmd: `.venv\Scripts\activate.bat`;
- не активировать вовсе и вызывать интерпретатор напрямую:
  `.venv\Scripts\python -m app.main IN\zp_basic.txt`.

`pytest` не обязателен (тесты работают и на стандартном `unittest`), но удобен:

```bat
py -m pip install pytest
```

### 3. Запустить программу

Все команды выполняются **из корня проекта** (там, где `app`, `IN`, `OUT`):

```bat
:: один файл, hex по умолчанию → ответ в IN\zp_basicout.txt
py -m app.main IN\zp_basic.txt

:: один файл, координаты в десятичном виде → ответ в OUT\
py -m app.main IN\zp_basic.txt -o OUT -f dec

:: вся папка IN → папка OUT
py -m app.main -i IN -o OUT
py -m app.main -i IN -o OUT -f dec
```

Прямые слеши тоже допустимы: `py -m app.main IN/zp_basic.txt`.

Для `IN\zp_basic.txt` при `-f dec` в `OUT\zp_basic.txt` должно быть:

```txt
(10, 6)
(10, 6)
O
O
```

### 4. Прогнать тесты

```bat
py -m unittest discover -s tests -v
:: или, если установлен pytest:
py -m pytest -q
```

Ожидается **69** тестов и `OK`. Тесты сверяются с эталонами из `OUT/`,
поэтому папка `OUT` должна присутствовать — она входит в репозиторий.

### Кодировка и консоль

Программа печатает сообщения со стрелкой `→`, а генераторы заданий печатали
`✅` (теперь печатают `OK`). Консоль Windows работает в `cp866`/`cp1251`, а
при перенаправлении вывода (файл, пайп, CI, окно Run в PyCharm) — в
`cp1251`/`cp437`; этих символов там нет, и печать падала с
`UnicodeEncodeError`, хотя ответы уже были записаны в файлы.

Сейчас это исправлено: `app/utils.py::configure_console()` вызывается в
начале `main()` и переводит `stdout`/`stderr` в режим `errors="replace"`.
Кодировка при этом **не меняется** — русский текст остаётся читаемым, а
непредставимые символы заменяются на `?`:

```txt
Готово: 15 файл(ов) обработано.
  ? OUT\k163_task.txt
```

Если хочется видеть стрелки без замены, разово переключите консоль в UTF-8:

```bat
chcp 65001
set PYTHONUTF8=1
py -m app.main -i IN -o OUT
```

В PowerShell: `$env:PYTHONUTF8 = "1"`. Windows Terminal использует UTF-8
по умолчанию, поэтому в нём всё отображается как есть.

**Файлы заданий** читаются как UTF-8. Обычно в них только цифры и латиница,
так что подходит файл в любой кодировке; если добавили русские комментарии —
сохраните файл в UTF-8 («Сохранить как → Кодировка: UTF-8»).
**Файлы ответов** всегда пишутся в UTF-8: строки `# Warning: …` на русском
корректно откроются в Notepad (Windows 10 сам определяет UTF-8) и в VS Code.

Переводы строк значения не имеют: принимаются и `LF`, и `CRLF`.

### Типичные ошибки на Windows

| Симптом | Причина и решение |
|---|---|
| `ModuleNotFoundError: No module named 'app'` | запуск не из корня проекта — сделайте `cd` в папку с `app\` |
| `python` открывает Microsoft Store | отключите псевдонимы выполнения приложений или используйте `py` |
| `UnicodeEncodeError: 'charmap' codec ...` | старая копия проекта — обновите (`git pull`) либо задайте `chcp 65001` и `set PYTHONUTF8=1` |
| `Activate.ps1 cannot be loaded ...` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или активация из cmd |
| `Нет эталона ... для ...` в тестах | в копии нет `OUT/` — обновите проект или выполните `py -m app.main -i IN -o OUT -f dec` |
| `Ошибка: Сингулярная кривая: ...` | кривая из задания вырождена — корректный отказ, а не сбой настройки |
| `Ошибка: Файл задания слишком короткий` | в файле меньше трёх строк: тип кривой, поле, коэффициенты |

## Ограничения и особенности

1. **Несингулярность проверяется автоматически:**
   - для `Zp`: `4·a³ + 27·b² ≠ 0 (mod p)`;
   - для `GF(2^m)`: `a6 ≠ 0`.
   
   При нарушении выбрасывается `ValueError`.

2. **Поддерживаются отрицательные скаляры** в операции `M`: `k < 0`
   трактуется как `(−k)·(−P)`.

3. **Число `k = 0`** даёт `O`.

4. **Число `k` больше порядка группы** обрабатывается корректно
   (double-and-add работает для любого целого `k`, включая `k > #E`).

5. **Точки, не лежащие на кривой**, не приводят к исключению — программа
   выводит предупреждение `# Warning` и продолжает сложение/умножение.
   Для надёжных результатов проверяйте предупреждения.

6. **Формат координат в ответах** задаётся флагом `-f hex|dec`
   (по умолчанию `hex`). На чтение входных файлов флаг не влияет.

7. **Многочлен-модуль** для `Nss`/`Ss` должен быть неприводимым над `Z_2`;
   программа **не проверяет** это — если модуль приводим, поле `FieldGF2m`
   не будет полем, и результат будет математически некорректным
   (хотя программа не упадёт).

8. **Порядок группы** программой не вычисляется и не используется —
   ни для `A`, ни для `M`. Если он нужен (например, для проверки, что
   точка порождает всю группу, или для оптимизации `mul` при очень
   больших `k`), его можно получить полным перебором:
   ```python
   from app.curves import CurveZp
   from app.point import Point
   
   c = CurveZp(17, 2, 2)
   n = 1
   for x in range(c.p):
       for y in range(c.p):
           if c.is_on_curve(Point(x, y)):
               n += 1
   print(n)   # порядок группы, включая O
   ```
   Для полей криптографического размера полный перебор неприменим;
   используются алгоритм Шуфа и его улучшения (SEA).

9. **Консольный вывод на Windows.** `configure_console()` включает
   `errors="replace"`, поэтому в консоли, чья кодовая страница не содержит
   `→`/`✅`, эти символы печатаются как `?`. На содержимое файлов ответов
   это не влияет — они всегда пишутся в UTF-8.

10. **Эталоны в `OUT/` — десятичные.** Они созданы запуском с `-f dec`;
    если пересоздавать их вручную, используйте тот же флаг, иначе
    `tests/test_files.py` сообщит о расхождении.
